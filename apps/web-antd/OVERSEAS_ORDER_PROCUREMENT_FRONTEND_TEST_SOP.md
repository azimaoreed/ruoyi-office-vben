# 海外订单采购流程前端功能测试 SOP

## 1. 文档目标

本文档用于指导 `apps/web-antd` 中海外订单采购流程相关前端功能的提测、自测和回归验证。覆盖本次需求新增或调整的 BPM 前端能力：

- 审批节点驳回模式：终止流程、退回重走、修改后继续；
- 驳回原因分类：补充资料、修改调整、风险校正、其他；
- 审批节点可配置允许发起修改申请；
- 修改申请支持子流程 Key、按钮名称、原因分类、恢复策略；
- 审批详情页支持发起修改申请、修改后继续、抄送；
- 任务列表、流程详情、流程图、版本/历史展示的基础回归；
- 前后端联调、构建、权限、异常和浏览器兼容验证。

适用范围：

- 仓库：`ruoyi-office-vben`
- 应用：`apps/web-antd`
- 主要模块：流程中心、流程模型、流程设计、待办任务、流程详情
- 默认前端地址：`http://localhost:5666`
- 默认后端地址：`http://127.0.0.1:48080`
- 默认接口前缀：`/admin-api`

## 2. 相关文件范围

前端测试时重点关注以下文件对应的页面能力：

| 功能 | 关键文件 |
| --- | --- |

| 流程详情操作按钮 | `apps/web-antd/src/views/bpm/processInstance/detail/modules/operation-button.vue` |
| SIMPLE 设计器枚举与节点模型 | `apps/web-antd/src/views/bpm/components/simple-process-design/consts.ts` |
| SIMPLE 审批节点配置 | `apps/web-antd/src/views/bpm/components/simple-process-design/components/nodes-config/user-task-node-config.vue` |
| SIMPLE 新增节点默认值 | `apps/web-antd/src/views/bpm/components/simple-process-design/components/nodes/node-handler.vue` |
| BPMN 自定义配置 | `apps/web-antd/src/views/bpm/components/bpmn-process-designer/package/penal/custom-config/components/UserTaskCustomConfig.vue` |
| 流程路由 | `apps/web-antd/src/router/routes/modules/bpm.ts` |

后端联调时需要确认以下接口可用：

| 接口 | 用途 |
| --- | --- |
| `PUT /admin-api/bpm/task/reject` | 驳回、退回重走、修改后继续 |
| `PUT /admin-api/bpm/task/start-modify-child-process` | 单独发起修改申请子流程 |
| `PUT /admin-api/bpm/task/copy` | 任务抄送 |
| `GET /admin-api/bpm/task/list-by-parent-task-id` | 查询主任务关联子任务 |
| `PUT /admin-api/bpm/task/withdraw-to-start` | 撤回到发起人 |

## 3. 测试环境准备

### 3.1 代码与依赖确认

在 `ruoyi-office-vben` 根目录执行：

```bash
git status --short
pnpm install
```

检查标准：

- 当前改动只包含本次需求相关文件；
- 未误改 `pnpm-lock.yaml`，除非确实新增或升级依赖；
- 无临时调试代码、无 `console.log`、无本地地址硬编码；
- 依赖安装使用 pnpm，不使用 npm 或 yarn。

### 3.2 后端服务确认

后端需启动并完成本次 BPM 表结构迁移。至少确认：

```bash
curl -fsS http://127.0.0.1:48080/actuator/health
```

返回示例：

```json
{"status":"UP"}
```

确认新增接口存在：

```bash
curl -fsS http://127.0.0.1:48080/v3/api-docs -o /tmp/ruoyi-api-docs.json

node - <<'NODE'
const fs = require('fs');
const j = JSON.parse(fs.readFileSync('/tmp/ruoyi-api-docs.json', 'utf8'));
const paths = [
  '/admin-api/bpm/task/reject',
  '/admin-api/bpm/task/start-modify-child-process',
  '/admin-api/bpm/task/copy',
  '/admin-api/bpm/task/list-by-parent-task-id',
  '/admin-api/bpm/task/withdraw-to-start',
];
for (const p of paths) console.log(`${p}: ${j.paths[p] ? Object.keys(j.paths[p]).join(',') : 'missing'}`);
NODE
```

通过标准：

- 以上接口均不是 `missing`；
- `reject` 请求体包含 `rejectMode`、`targetTaskDefinitionKey`、`rejectReasonType`、`rejectDetail`、`childProcessDefinitionKey`、`modifyPayload`、`resumeStrategy`；
- `start-modify-child-process` 请求体包含 `childProcessDefinitionKey`、`reasonType`、`reasonDetail`、`modifyPayload`、`resumeStrategy`。

### 3.3 前端启动

在 `ruoyi-office-vben` 根目录执行：

访问：

http://localhost:5666

## 6. SIMPLE 设计器专项测试

### 6.1 新增审批节点默认值

操作步骤：

1. 创建 SIMPLE 流程；
2. 在“流程设计”中点击节点之间的加号；
3. 新增“审批人”节点；
4. 打开审批节点配置面板。

验收标准：

- 新增审批节点名称默认为审批节点语义名称；
- 默认审批方式可正常显示；
- 驳回处理默认存在；
- `允许原因分类` 默认包含补充资料、修改调整、风险校正、其他；
- `允许发起修改申请` 默认关闭；
- 默认按钮名称为“发起修改申请”；
- 默认恢复策略为“继续当前主流程节点”。

### 6.2 驳回模式配置

操作步骤：

1. 打开 SIMPLE 审批节点配置；
2. 找到驳回处理配置；
3. 分别选择以下驳回模式：
   - 终止流程；
   - 退回重走；
   - 修改后继续；
4. 设置驳回目标范围：
   - 运行时选择；
   - 固定节点；
   - 表达式节点。
5. 设置允许原因分类。

验收标准：

- 驳回模式选项文案正确；
- 选择“退回重走”时，可配置目标范围；
- 选择“固定节点”时展示固定退回节点；
- 表达式节点如当前版本不支持，应保持禁用；
- 允许原因分类可多选、清空、重新选择；
- 保存后重新进入模型，配置可正确回显；
- 导出或保存的模型数据中包含 `rejectHandler.type`、`targetType`、`returnNodeId`、`reasonTypes`。

### 6.3 允许发起修改申请配置

操作步骤：

1. 打开 SIMPLE 审批节点配置；
2. 找到“允许发起修改申请”；
3. 打开启用开关；
4. 填写按钮名称，例如“发起采购资料修改”；
5. 填写修改子流程 Key，例如 `purchase_modify_sub_process`；
6. 选择默认恢复策略；
7. 设置允许原因分类；
8. 保存模型并重新打开。

验收标准：

- 开关关闭时隐藏子配置项；
- 开关打开时展示按钮名称、修改子流程 Key、默认恢复策略、允许原因分类；
- 子流程 Key 必填或业务校验符合当前实现；
- 按钮名称为空时有默认值或合理校验；
- 原因分类可限制运行时可选项；
- 保存后重新打开可正确回显；
- 模型数据中包含 `modifyProcessSetting.enable`、`buttonName`、`childProcessDefinitionKey`、`resumeStrategy`、`reasonTypes`。

### 6.4 恢复策略配置

操作步骤：

1. 在“允许发起修改申请”中选择“继续当前主流程节点”；
2. 保存并重新打开；
3. 再切换为“回到指定节点”；
4. 保存并重新打开。

验收标准：

- 两种策略可切换；
- 重新进入后保持最后保存值；
- 运行时提交给后端的 `resumeStrategy` 与配置一致；
- 不同策略下前端无异常提示或空白配置。

### 6.5 子流程节点配置回归

操作步骤：

1. 在 SIMPLE 设计器中新增“子流程”节点；
2. 配置调用流程、是否异步、跳过发起人节点；
3. 配置入参、出参；
4. 配置超时处理；
5. 配置多人审批或并行能力；
6. 保存并重新打开。

验收标准：

- 子流程节点仍可正常新增、配置、保存、回显；
- 入参、出参不被本次修改影响；
- 异步子流程图标和文案正确；
- 超时处理配置不丢失；
- 不影响“允许发起修改申请”中的修改子流程配置。

## 8. 流程运行时专项测试

### 8.1 流程发布与发起

操作步骤：

1. 保存并发布测试流程；
2. 进入“发起流程”；
3. 找到测试流程；
4. 填写业务表单；
5. 提交发起。

验收标准：

- 已发布流程可在发起列表出现；
- 表单正常渲染；
- 提交成功后生成流程实例；
- “我的流程”可查询到该实例；
- 流程详情可打开，流程图正常展示。

### 8.2 审批详情页驳回模式

前置条件：

- 当前登录账号拥有待办任务；
- 审批节点启用了“驳回”按钮；
- 节点配置了驳回模式和原因分类。

操作步骤：

1. 进入“待办任务”；
2. 打开目标流程详情；
3. 点击“驳回”；
4. 检查弹窗字段；
5. 分别测试：
   - 终止流程；
   - 退回重走；
   - 修改后继续。

验收标准：

- 弹窗展示“驳回模式”“原因分类”“原因说明”；
- 选择“退回重走”时展示“目标节点”；
- 无可退回节点时显示“当前没有可重走的历史节点，本次仅支持终止流程。”；
- 运行时原因分类只展示节点允许的分类；
- 原因说明必填或校验符合需求；
- 提交成功后有成功提示；
- 成功后详情页任务状态、流程图和按钮状态刷新正确。

### 8.3 修改后继续

前置条件：

- 审批节点驳回模式允许“修改后继续”；
- 节点配置了修改子流程 Key；
- 后端存在对应子流程定义。

操作步骤：

1. 打开待办详情；
2. 点击“驳回”；
3. 驳回模式选择“修改后继续”；
4. 选择原因分类；
5. 填写原因说明；
6. 如页面支持启动参数，输入合法 JSON；
7. 提交。

验收标准：

- “修改后继续”选项可见；
- 选中后不要求选择退回目标节点；
- 提交请求为 `PUT /admin-api/bpm/task/reject`；
- 请求体包含 `rejectMode=3`；
- 请求体包含 `childProcessDefinitionKey` 和 `resumeStrategy`；
- 合法 JSON 可正常提交；
- 非法 JSON 有前端提示，不发送错误请求；
- 成功提示为“已发起修改申请”或符合当前设计；
- 主流程任务进入冻结/等待修改状态，不能重复处理同一任务；
- 关联子流程可在详情或任务列表中追踪。

### 8.4 单独发起修改申请按钮

前置条件：

- 节点启用了“允许发起修改申请”；
- 当前运行节点的 `modifyProcessSetting.enable=true`；
- 当前用户拥有该待办任务。

操作步骤：

1. 打开待办详情；
2. 查找自定义按钮，例如“发起修改申请”或配置的按钮名称；
3. 点击按钮；
4. 检查弹窗字段：
   - 修改子流程；
   - 原因分类；
   - 原因说明；
   - 启动参数(JSON)；
5. 输入合法数据并提交。

验收标准：

- 按钮名称与模型配置一致；
- 弹窗展示子流程 Key；
- 原因分类受模型配置限制；
- 原因说明必填；
- 启动参数支持合法 JSON；
- 非法 JSON 有明确提示；
- 提交接口为 `PUT /admin-api/bpm/task/start-modify-child-process`；
- 请求体包含 `id`、`childProcessDefinitionKey`、`reasonType`、`reasonDetail`、`resumeStrategy`；
- 成功后提示“已发起修改申请”；
- 重复点击不会产生重复子流程。

### 8.5 退回重走

前置条件：

- 流程已经经过至少一个历史审批节点；
- 当前节点配置允许“退回重走”；
- 当前节点的驳回目标配置为运行时选择或固定节点。

操作步骤：

1. 打开待办详情；
2. 点击“驳回”；
3. 选择“退回重走”；
4. 选择目标节点；
5. 填写原因分类和原因说明；
6. 提交；
7. 使用目标节点审批人账号登录查看待办。

验收标准：

- 目标节点列表只包含可退回历史节点；
- 固定节点模式下目标节点不可随意修改；
- 成功后当前任务结束；
- 目标节点产生新待办；
- 流程图显示退回后的运行节点；
- 流程详情中保留驳回原因和版本/历史信息。

### 8.6 终止流程

操作步骤：

1. 打开待办详情；
2. 点击“驳回”；
3. 选择“终止流程”；
4. 选择原因分类；
5. 填写原因说明；
6. 提交。

验收标准：

- 提交接口为 `PUT /admin-api/bpm/task/reject`；
- 请求体 `rejectMode=1`；
- 成功后流程实例状态变为已拒绝或终止；
- 待办列表中不再展示该任务；
- 详情页操作按钮隐藏或禁用；
- 流程图展示终态。

- 已办详情只读；
- 操作记录、原因、时间展示正确。

验收标准：

- 已办列表能查到记录；
- 详情无可重复办理按钮；
- 版本/历史信息不丢失。

### 10.3 我的流程

测试项：

- 发起人查看流程状态；
- 退回重走后状态变化；
- 修改后继续时主流程冻结或等待状态；
- 子流程完成后状态恢复。

验收标准：

- 列表状态与详情一致；
- 流程摘要不丢失；
- 流程图当前节点正确。

### 10.4 抄送我的

测试项：

- 被抄送用户登录；
- 查看抄送列表；
- 打开抄送详情。

验收标准：

- 抄送记录可见；
- 抄送原因可见；
- 详情只读；
- 无审批操作按钮。

## 11. 异常场景测试

### 11.1 JSON 参数异常

操作步骤：

1. 在“启动参数(JSON)”输入 `{abc`；
2. 点击提交。

验收标准：

- 前端提示 JSON 格式错误；
- 不发送后端请求，或后端错误被清晰展示；
- 表单数据不丢失；
- 修正 JSON 后可再次提交。

### 11.2 子流程 Key 不存在

操作步骤：

1. 配置不存在的修改子流程 Key；
2. 发起修改申请。

验收标准：

- 后端返回错误时前端明确提示；
- 主流程状态不应被前端误判为成功；
- 按钮 loading 能恢复；
- 可重新提交正确 Key。

### 11.3 无权限或登录过期

操作步骤：

1. 清除 token 或使用无权限账号访问详情；
2. 直接访问待办详情 URL；
3. 尝试提交审批操作。

验收标准：

- 登录过期跳转登录页；
- 无权限有明确提示；
- 不展示不应出现的操作按钮；
- 不通过前端路由绕过权限。

### 11.4 接口失败

操作步骤：

1. 临时停止后端或制造 500 响应；
2. 点击驳回、修改申请、抄送；
3. 恢复后端后重试。

验收标准：

- 错误提示清晰；
- loading 状态恢复；
- 表单数据保留；
- 不重复创建子流程或抄送记录；
- 网络恢复后可重试。

## 13. Network 检查清单

在浏览器 DevTools Network 中重点检查：

| 操作 | 期望接口 | 关键参数 |
| --- | --- | --- |
| 打开流程模型 | `/admin-api/bpm/model/**` | `id`、`type` |
| 保存 SIMPLE 模型 | `/admin-api/bpm/model/update` 或 `/update-bpmn` | `simpleModel`、`rejectHandler`、`modifyProcessSetting` |
| 打开待办详情 | `/admin-api/bpm/process-instance/get-approval-detail` | `id` |
| 驳回 | `/admin-api/bpm/task/reject` | `rejectMode`、`rejectReasonType`、`rejectDetail` |
| 修改后继续 | `/admin-api/bpm/task/reject` | `rejectMode=3`、`childProcessDefinitionKey`、`resumeStrategy` |
| 发起修改申请 | `/admin-api/bpm/task/start-modify-child-process` | `childProcessDefinitionKey`、`reasonType`、`reasonDetail` |
| 抄送 | `/admin-api/bpm/task/copy` | `copyUserIds`、`copyRoleIds`、`copyDeptIds` |

通过标准：

- 接口状态码为业务成功；
- 无新增 404、500、502；
- 请求参数与 UI 选择一致；
- 不传空字符串覆盖有效配置；
- token、tenant-id、加密头符合当前环境要求。

## 14. 数据库辅助核对

前端测试不直接以数据库为验收依据，但联调问题定位时可辅助核对。

本地 Docker MySQL 示例：

```bash
docker exec ruoyi-office-mysql-test mysql -uroot -pRuoYi@2024! ruoyi-office -e "
SELECT COUNT(*) FROM bpm_process_instance_version;
SELECT COUNT(*) FROM bpm_reject_history;
SELECT COUNT(*) FROM bpm_parent_child_process_link;
SELECT COUNT(*) FROM bpm_frozen_task;
"
```

核对点：

- 驳回后 `bpm_reject_history` 有记录；
- 退回重走后版本信息有变化；
- 修改申请后 `bpm_parent_child_process_link` 有主子流程关联；
- 修改申请期间主任务冻结信息符合预期；
- 子流程完成后冻结任务状态被恢复或结束。
