## 部署要点

### 1. Monorepo 依赖处理

由于 web-antd 依赖 workspace 中的其他包，必须：

- 在项目根目录执行 `pnpm install`
- 使用 `--frozen-lockfile` 确保依赖一致性
- Jenkinsfile 已正确处理

### 2. Base 路径配置

生产环境必须配置 `base: '/web/'`：

- 确保静态资源路径正确
- 开发环境使用 `base: '/'`
- 通过 `process.env.NODE_ENV` 区分

### 3. Nginx Location 配置

使用 `alias` 而非 `root`：

```nginx
location /web {
    alias /usr/share/nginx/html/web;  # 使用 alias
    try_files $uri $uri/ /web/index.html;  # SPA 路由
}
```

### 4. pnpm 安装

Jenkins 容器需要安装 pnpm：

- Jenkinsfile 会自动检测并安装
- 或手动安装：`npm install -g pnpm`

## 快速开始

### 最简步骤

1. **配置 Jenkins**（5 分钟）

   ```bash
   # 安装 pnpm
   docker exec jenkins npm install -g pnpm

   # 创建 Pipeline 任务
   # 仓库: git@codeup.aliyun.com:676b69e335730943ed494c52/ruoyi-office/ruoyi-office-vben.git
   # 脚本: apps/web-antd/Jenkinsfile
   ```

2. **配置 Nginx**（3 分钟）

   ```bash
   # 创建目录
   mkdir -p /data/nginx/html/web

   # 添加配置（参考 nginx/web-antd.conf）
   vi /data/nginx/conf/conf.d/default.conf

   # 重新加载
   docker exec nginx nginx -s reload
   ```

3. **执行部署**（3-5 分钟）
   - Jenkins 点击"立即构建"
   - 等待构建完成

4. **访问验证**
   - 浏览器打开: http://182.92.106.252/web
   - 验证页面正常显示

**总耗时**: 约 15 分钟

## 常见问题

### Q1: 为什么使用 pnpm 而不是 npm？

**A**: 因为项目使用 Monorepo 架构，pnpm 对 workspace 支持更好，且速度更快、占用空间更小。

### Q2: 为什么需要配置 base 路径？

**A**: 因为应用部署在 `/web` 子路径下，不配置 base 会导致静态资源路径错误（404）。

### Q3: 可以不使用 Publish Over SSH 插件吗？

**A**: 可以，可以使用 `sshagent` + `tar + ssh` 方式，但 Publish Over SSH 更简洁、日志更清晰。

### Q4: 构建需要多长时间？

**A**: 首次构建约 3-5 分钟（需要安装依赖），后续构建约 2-3 分钟。

### Q5: 如何回滚到上一个版本？

**A**: 参考 `DEPLOYMENT_CHECKLIST.md` 中的回滚操作部分。
